Converting datasets

fgba convert reads a source format into a FlatGeobuf body (spatial index on, WGS 84) and appends the aggregate trailer — one command, deterministic output.

fgba convert buildings.geojson -o buildings.a.fgb
fgba convert tracks.csv       -o tracks.a.fgb
fgba convert parcels.shp      -o parcels.a.fgb
fgba convert existing.fgb     -o existing.a.fgb   # = fgba build

Supported inputs§

FormatExtensionNotes
GeoJSON.geojson, .json FeatureCollection, single Feature, or bare geometry.
CSV / TSV.csv, .tsv A WKT column (wkt, geom, geometry, the_geom) or an x/y column pair (x/lon/lng/long/longitude/easting with y/lat/latitude/northing; case-insensitive). Rows with empty or unparseable geometry are skipped and reported.
Shapefile.shp Properties are read from the .dbf sidecar when present; a missing sidecar still yields geometry-only features. Z/M ordinates are dropped; NullShape and Multipatch records are skipped.
FlatGeobuf.fgb The body is kept byte-identical; only the trailer is built. An existing trailer is rebuilt from its body and written atomically to the output, including safe in-place rebuilds. fgba build uses a default output name (x.fgb → x.a.fgb) when none is supplied.
GeoParquet.parquet Not in v0.1 — fails with a clear "not implemented yet" error. Planned.
GeoPackage.gpkg Not in v0.1 — fails with a clear "not implemented yet" error. Planned.

Deterministic property preservation§

Conversion retains source properties instead of discarding them. The whole schema is inferred before writing, columns have deterministic name order, and missing or explicit null values make a column nullable. Numeric types stay lossless: signed widths widen to Long, unsigned widths to ULong, and Float/Double mixtures to Double. Incompatible types are errors rather than silent string coercion.

Case-insensitive duplicate property names and collisions with the reserved SQL names geom_wkb, bbox_xmin, bbox_ymin, bbox_xmax, bbox_ymax, geom_length, geom_area, and geom_npoints are rejected. FlatGeobuf inputs keep their entire body byte-identical. Shapefile DBF values are preserved when the sidecar exists; a missing DBF intentionally produces geometry-only features.

Optional analytical columns§

Add --analytics to either conversion or an existing-FGB build. --chunk-rows auto adapts the chunk height by default; an explicit positive size such as 4096 overrides it:

fgba convert cities.geojson --analytics --chunk-rows 4096 -o cities.a.fgb
fgba build cities-metrics.fgb --analytics --chunk-rows 4096 -o cities-metrics.a.fgb

When property columns exist, this adds one kind-2 BODY_ANALYTICS section with exact global statistics, per-chunk numeric/null zone maps and body offsets, and independent Arrow IPC property chunks. A property-free body gets no empty section. Ordinary builds remain unchanged, and neither the footer nor directory version changes. Query the result with native SQL and analytics.

CRS: WGS 84 lon/lat required§

The output body is written as WGS 84 (EPSG:4326, lon/lat degrees), and A5 cell binning assumes lon/lat. convert does not reproject: feed it coordinates already in WGS 84. Reproject first with another tool (e.g. ogr2ogr -t_srs EPSG:4326) if your source is in a projected CRS. Features with empty or unusable geometry are skipped and counted in the report (0 skipped means a clean read).

The band ladder§

The builder chooses the base resolution automatically — the smallest res ≥ 2 whose cell count is at least 4× the feature count, capped at 16 — and writes bands at {base, base−2, base−4, …} while the resolution stays ≥ 2, at most 6 bands (SPEC §8). The 12-feature quickstart file gets a single band at resolution 2; a 1M-point dataset gets five bands (res 15 down to 7). Every feature is binned by the midpoint of its bounding box, so each band is a lossless partition: counts sum to the feature count.

Determinism§

Identical input and options produce byte-identical output (SPEC §8) — safe for CDN caching, diff distribution, and checksum verification. Writes are atomic (temporary file plus rename), so a failed conversion never leaves a truncated output. Files are write-once: to change data, rebuild from the source rather than editing an existing file.

After converting, fgba verify checks the structure end to end (body, CRC-verified directory, every band's ascending cells and exact partition), and xtask verify-vectors pins the committed test vector's checksums — see the repository.
