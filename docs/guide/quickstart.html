Quickstart

Install the CLI, turn a GeoJSON file into an FGBA file, verify it, query it, and stream it over HTTP — in about a minute.

Install§

# the command-line tool
cargo install fgba-cli

# or, from a checkout of the repository:
cargo install --path crates/fgba-cli
The crates are version 0.1 implementing the draft v1 specification. The CLI binary is called fgba; the library crate is also called fgba.

Convert a dataset§

Point fgba convert at a GeoJSON, CSV/TSV, Shapefile or FlatGeobuf file (details and limits in Converting datasets):

$ fgba convert cities.geojson -o cities.a.fgb
converted cities.geojson → cities.a.fgb (12 features, 0 skipped)
  features: 12 (0 skipped)
  bands: 2
  trailer: 105 B
  total size: 1.6 KiB
  wall time: 1.02 ms

The output is a valid FlatGeobuf file with a 105-byte aggregate trailer — one band at A5 resolution 2 for this 12-feature input. If you already have a FlatGeobuf file, fgba build existing.fgb appends the trailer in place of a conversion (output defaults to existing.a.fgb), and keeps the body byte-identical.

Inspect and verify§

$ fgba info cities.a.fgb
cities.a.fgb — FGBA
  body: FlatGeobuf "cities", 12 features, Point, index node size 16
  envelope: [-74.02, 40.7, 2.37, 51.52]
  sizes: body 1.5 KiB, trailer 105 B, total 1.6 KiB
  bands: 1
    res  2: 2 cells, 44 B
$ fgba verify cities.a.fgb
verify cities.a.fgb
  body: 12 features, Point — OK
  footer + directory: CRC verified — OK
  band res 2: 2 cells, 12 features — OK
OK: valid FGBA, 12 features, 1 band(s)

Query counts§

stats answers "how many features are in this bounding box" from the trailer alone, without touching feature bytes:

$ fgba stats cities.a.fgb --bbox -11,35,31,71
bbox [-11, 35, 31, 71] res 2
  cells matched: 1
  estimated features: 8

London and Paris share one A5 cell at resolution 2, so the Europe bounding box reports 8 of the 12 features. --res picks a band explicitly; the default is the file's deepest band.

Serve over HTTP§

fgba serve is a minimal range-capable static server bound to loopback — enough to exercise HTTP reading end to end. (For production hosting see Hosting.)

$ fgba serve cities.a.fgb
serving /home/user/lab/cities.a.fgb on http://127.0.0.1:8080 (range requests; ctrl-c to stop)

Probe the range support, exactly as a reader does (SPEC §9.2 step 1):

$ curl -H 'Range: bytes=0-0' -D - -o /dev/null http://127.0.0.1:8080/
HTTP/1.1 206 Partial Content
Content-Length: 1
Content-Range: bytes 0-0/1641
Accept-Ranges: bytes
Content-Type: application/octet-stream

Then read it over HTTP with the http_reader example — opening costs 3 requests (probe, footer, directory) and each band is fetched once.

Open in a browser§

The dependency-free wasm canvas demo draws the aggregate cells straight off any static host. Serve the repository root and open the demo page:

# from the repository root
fgba serve .
# open http://127.0.0.1:8080/crates/fgba/examples/wasm/index.html

The page loads the committed test vector (testdata/cities_12.a.fgb) by default and reports 3 range requests — footer, directory, band. Point it at your own file with ?url=.
