Examples

Three runnable examples ship in the repository, from smallest to most end-to-end. All of them run against the committed 12-feature test vector (testdata/cities_12.a.fgb, the normative vector of SPEC Appendix A).

read_write — library round trip§

crates/fgba/examples/read_write.rs builds a small FlatGeobuf body in memory (the 12 cities of the test vector), appends the aggregate trailer with fgba::build, writes the file to a temporary directory, reopens it with Reader::open_path, and answers count queries from the trailer alone.

$ cargo run -p fgba --example read_write
body: 12 cities, 1528 bytes of FlatGeobuf
trailer: 105 bytes, band(s) at A5 resolution 2
wrote /tmp/cities.a.fgb (1633 bytes) and reopened it
body length: 1528 bytes (the trailer starts there)
  band res 2: 2 cells, 12 features, 44 bytes at offset 1532
stats over Europe [-11, 35, 31, 71] @ res 2: 1 cell(s), ~8 features
query over New York [-75, 39, -72, 42] @ res 2:
  cell 0x2680000000000000: 4 features
stats over the world: 2 cell(s), ~12 features

http_reader — over HTTP range requests§

crates/fgba/examples/http_reader.rs reads an FGBA file off any range-capable host with Reader::open_url (the http feature), printing the bands, one count query, and the transport counters. Try it against the test vector served by the CLI:

$ fgba serve testdata/cities_12.a.fgb &
serving …/testdata/cities_12.a.fgb on http://127.0.0.1:8080 (range requests; ctrl-c to stop)

$ cargo run -p fgba --example http_reader --features http -- http://127.0.0.1:8080/
http://127.0.0.1:8080/ — FGBA over HTTP range requests
body length: 1672 bytes
  band res 2: 2 cells, 12 features (44 bytes)
stats over the world @ res 2: 2 cell(s), ~12 features
http: 5 requests, 146 bytes read

Five requests, 146 bytes, for every answer: the range probe, the 32-byte footer, the 25-byte directory, and the 44-byte band — then the world-view query reuses the cached band (SPEC §9.2).

wasm — two-phase streaming in the browser§

crates/fgba/examples/wasm/ is a dependency-free canvas demo of the two-phase read pattern (SPEC §9.3): fetch the file's last 32 bytes and parse the footer (doubling as the range-support probe), fetch and CRC-verify the directory, fetch the deepest band under the 8 MiB cap, then draw the counted A5 pentagons of the world view on a 2D canvas. Only the A5 grid math is imported (the official a5-js, via an import map); footer/directory/band parsing and the CRC are pure byte work in main.js. No build step, no map library, no server-side code — the page and the data just have to share an origin (the Range header triggers a CORS preflight otherwise).

# from the repository root
$ fgba serve .
# open http://127.0.0.1:8080/crates/fgba/examples/wasm/index.html

With the default test vector the page draws the two occupied res-2 pentagons (one over New York, one over Western Europe) and reports:

bands: res 2 (44 B)
drew res 2: 2 of 2 occupied cells cover the world view, ~12 of 12 features
3 range requests, 101 bytes transferred

Point it at any other .a.fgb with the input box or ?url=. For fully offline use, copy a5-js's dist/a5.js next to the page and point the import map at ./a5.js — any host that answers 206 Partial Content works for the data, and the demo says so when one does not.

All command outputs above are real captures from the reference machine (2026 laptop, loopback HTTP), reproduced by running the examples against the committed test vector.
