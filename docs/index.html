FGBAFlatGeobuf Aggregates

A cloud-optimized vector format: full-fidelity FlatGeobuf features plus precomputed A5 aggregate cells, streamable over plain HTTP range requests.

An FGBA file is a FlatGeobuf file — every existing FGB reader (GDAL, QGIS, the JS and Rust libraries) reads all features from it unchanged. After the feature data, a small trailer carries counted, equal-area A5 pentagon cells at several resolutions. Readers that know the trailer get instant low-zoom overviews and count analytics, locally or straight off S3/R2/static hosting; readers that don't never notice it.

┌─────────────────────────────────────────────┐
│ plain FlatGeobuf (full resolution features) │ ← readable by any FGB reader
├─────────────────────────────────────────────┤
│ aggregate bands (cell, count) by resolution │ ← FGBA-aware readers get
│ directory · footer (32B discovery at EOF)   │   fast at every zoom
└─────────────────────────────────────────────┘

Quickstart

# install the CLI
cargo install fgba-cli

# convert a dataset (GeoJSON / CSV / Shapefile / FGB) and inspect it
fgba convert buildings.geojson -o buildings.a.fgb
fgba info buildings.a.fgb
fgba query buildings.a.fgb "SELECT COUNT(*) FROM features"

# serve it over loopback HTTP with range requests and open the viewer demo
fgba serve buildings.a.fgb
// Cargo.toml: fgba = { version = "0.1", features = ["http"] }
// Count analytics straight off static hosting — a few hundred bytes:
let mut r = fgba::Reader::open_url("https://example.com/buildings.a.fgb")?;
let cells = r.query([-0.5, 51.3, 0.3, 51.7], 7)?;
let total = r.stats([-180.0, -85.0, 180.0, 85.0], 2)?.total;

The Format

A binary extension of FlatGeobuf: a valid FGB body, then a trailer of aggregate bands — per-resolution arrays of (A5 cell, count) records, curve-sorted so a viewport covering is a few contiguous runs. A 32-byte footer at end-of-file discovers a CRC-verified, kind-tagged directory; unknown sections are skipped, never failed on. Deterministic, write-once, and documented to the byte.

Library & Tools

The reference implementation is a Rust library plus a command-line tool — version 0.1 implementing the draft v1 spec.

cargo add fgba
cargo install fgba-cli

docs.rs/fgba · crates.io/crates/fgba · crates.io/crates/fgba-cli

fgba query and fgba-sql provide native read-only SQL; optional kind-2 analytics add property statistics and independent Arrow IPC chunks. See the native SQL & analytics guide.

The core crate builds for wasm32-unknown-unknown: in the browser, fetch byte ranges asynchronously and decode with SliceReader — two phases, no blocking (guide, browser demo).

The Numbers

Measured on a synthetic 1M-point dataset (117 MiB body), release build:

build: FGB encode + 5 bands2.5 s + 1.1 s
trailer size2.43 MiB (~2%)
aggregate query per viewport2–91 µs
HTTP: open (probe+footer+dir)3 requests, 120 B
HTTP: first view of current band1 request
HTTP: warm same-resolution viewport0 band requests

Reference machine: a 2026 laptop, 2026-10-18; HTTP over loopback. Methodology and caveats in SPEC Appendix B.
